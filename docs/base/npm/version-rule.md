# 语义化版本规范

## 语义化版本规范 (Semantic Versioning, SemVer) 详细说明

---

### **1. 定义**

**语义化版本规范（SemVer）** 是一种标准化的版本号命名规则，旨在通过明确的版本号变化规则，传递代码变更的**兼容性信息**。其核心目标是解决软件依赖管理中的“依赖地狱”问题，帮助开发者清晰判断升级版本是否安全。

---

### **2. 版本号格式**

SemVer 版本号格式为：**`主版本号.次版本号.修订号`**，形如 `X.Y.Z`（如 `2.4.1`），其中：

- **`X`（主版本号, Major）**：发生 **不兼容的 API 变更** 时递增。
- **`Y`（次版本号, Minor）**：新增 **向下兼容的功能** 时递增。
- **`Z`（修订号, Patch）**：修复 **向下兼容的问题** 时递增。

#### **扩展格式**

允许附加 **预发布版本** 和 **构建元数据**：

- **预发布版本**：`X.Y.Z-alpha.1`、`2.0.0-beta`（表示不稳定版本）。
- **构建元数据**：`X.Y.Z+20240101`、`3.1.0-rc.1+sha.1234`（附加编译信息，不影响版本优先级）。

---

### **3. 版本号递增规则**

| 变更类型                     | 递增规则                  | 示例（旧 → 新）      |
|------------------------------|--------------------------|---------------------|
| **破坏性变更**（API 不兼容） | **主版本号**（X+1，Y归零，Z归零） | `1.4.3` → `2.0.0`  |
| **新增功能**（向下兼容）      | **次版本号**（Y+1，Z归零）       | `2.1.7` → `2.2.0`  |
| **问题修复**（向下兼容）      | **修订号**（Z+1）                | `3.0.1` → `3.0.2`  |

---

### **4. 版本范围语法**

在依赖声明（如 `package.json`）中，使用特定符号定义允许的版本范围：

#### **4.1 基本语法**

| 语法            | 说明                                                                 | 示例                |
|------------------|----------------------------------------------------------------------|---------------------|
| **`^X.Y.Z`**     | 允许主版本号固定，次版本号和修订号可更新（`X` 非零时）               | `^2.3.4` → `≥2.3.4 <3.0.0` |
| **`~X.Y.Z`**     | 允许主版本号和次版本号固定，修订号可更新                             | `~1.2.3` → `≥1.2.3 <1.3.0` |
| **`>X.Y.Z`**     | 必须大于指定版本                                                     | `>2.0.0`            |
| **`>=X.Y.Z`**    | 必须大于等于指定版本                                                 | `>=1.5.0`           |
| **`<X.Y.Z`**     | 必须小于指定版本                                                     | `<3.0.0`            |
| **`X.Y.Z - A.B.C`** | 闭区间（含两端）                                                   | `1.2.3 - 2.0.0`     |

#### **4.2 特殊语法**

| 语法            | 说明                                                                 |
|------------------|----------------------------------------------------------------------|
| **`*` 或 `x`**   | 通配符（允许任意版本），如 `2.x` 表示 `≥2.0.0 <3.0.0`。             |
| **`latest`**     | 安装最新版本（不推荐，可能导致破坏性变更）。                        |

---

### **5. 预发布版本处理**

预发布版本（如 `alpha`、`beta`、`rc`）需显式指定范围才会被安装：

```json
{
  "dependencies": {
    "pkg": "^1.0.0-alpha.1"  // 允许安装预发布版本
  }
}
```

#### **预发布标识符优先级**

按字典序排序，如：
`1.0.0-alpha` < `1.0.0-alpha.1` < `1.0.0-beta` < `1.0.0-rc.1` < `1.0.0`.

---

### **6. 核心规范要求**

1. **版本号必须为 `X.Y.Z` 格式**：X、Y、Z 为非负整数，禁止前导零（如 `01.2.3` 无效）。
2. **主版本号为零（`0.Y.Z`）**：表示初始开发阶段，**任何变更都可能破坏兼容性**。
3. **公共 API 必须明确定义**：版本号变更需基于公共 API 的变更。
4. **版本号递增后必须重置低位**：如主版本号递增后，次版本号和修订号归零。
5. **构建元数据不影响优先级**：`1.0.0+2023` 和 `1.0.0+2024` 视为相同版本。

---

### **7. 版本比较规则**

1. **逐级比较**：先比较主版本号，再依次比较次版本号、修订号。
2. **预发布版本优先级低于正式版本**：`1.0.0-alpha` < `1.0.0`。
3. **数值比较**：`1.9.0` < `1.10.0`（按数值 9 < 10 判断，非字符串比较）。

---

### **8. 工具支持**

- **npm / Yarn**：自动解析版本范围并安装兼容版本。
- **语义化版本校验工具**（如 `semver` 包）：
  ```javascript
  const semver = require('semver');
  semver.valid('1.2.3');         // 返回 '1.2.3'（有效）
  semver.satisfies('1.2.3', '^1.0.0'); // 返回 true
  ```

---

### **9. 应用场景**

1. **依赖声明**：控制第三方库的更新范围（如 `^2.3.0`）。
2. **发布包版本**：通过版本号告知用户升级风险。
3. **CI/CD 流程**：根据版本号自动触发发布流程（如 `alpha` 版本部署到测试环境）。

---

### **10. 常见错误**

- **主版本号为零时随意变更**：`0.Y.Z` 版本本应视为不稳定，但开发者可能误认为其稳定。
- **忽略 `package-lock.json` / `yarn.lock`**：导致依赖版本浮动，破坏稳定性。
- **手动修改版本号**：未通过工具（如 `npm version`）规范递增。

---

### **11. 总结**

语义化版本规范通过严格的版本号规则，实现以下目标：

- **明确性**：通过版本号传达变更的兼容性。
- **自动化**：依赖管理工具可安全选择版本。
- **协作性**：开发者与用户对版本预期一致。

遵循 SemVer 能显著提升软件的可维护性和生态协作效率，是现代软件开发（尤其是开源项目）的基石规范。
